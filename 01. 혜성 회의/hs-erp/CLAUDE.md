# 혜성물류 회의자료 (구 혜성물류 운영 ERP) — Claude Code 작업 안내

이 파일은 Claude Code 가 이 폴더를 열면 맨 먼저 읽는 안내서입니다. 아래 규칙을 지켜 이어서 작업하세요.

## 1. 누구를 위한 무엇인가
- 사용자: **행님** (혜성물류(주) 물류관리팀 부장). 스스로 "완전 컴맹"이라 함 → **쉬운 한국어**로, 기술 용어 없이 설명. 문서·매뉴얼은 PDF 선호.
- 프로그램: 혜성물류 고백리 · 안성 센터의 운영 웹앱. 2026-11-09 부터 **"혜성물류 회의자료"** (월간 회의 자료 통합 · 현장 회의 자료 간소화)가 중심.
- 구조: 정적 SPA (`site/`) + Supabase(무료) DB (`sql/`) + Cloudflare Pages 배포. 서버 코드 없음.
- 파일 · 프로그램 이름은 **한글**, 브랜드명만 영문 (예: PING, MAMMUT).

## 2. 일하는 방식 (꼭 지킬 것)
1. **질문 → 시안 이미지 → 승인 → 제작** 순서. 사용자가 "바로 작업해"라고 하면 바로 제작.
   - 시안은 실제 화면 모양을 HTML 로 그려 Playwright 로 PNG 를 찍어 보여 줌 (숫자는 실제 자료로, 화면 안에서만).
2. **Gemini 와 같이 작업** (모든 프로젝트 공통 · 크레딧 절약 목적): 아이디어 · 방안 제안 · 코드 버그 검토는 Gemini 에 맡기고, Claude 는 제작 · 검증.
   - Gemini 에는 **코드와 표 · 시트 이름만** 보냄. 회사 숫자 · 화주 자료 · 개인정보는 보내지 않음.
   - Gemini 지적은 하나씩 코드로 확인해서 진짜 버그만 고치고, 결과를 사용자에게 알림.
3. 제작 후 **테스트 전부 돌려 확인** → 업데이트 파일(zip) 전달 → 사용자가 `업데이트하기.bat` 실행.
4. 답은 짧게: 무엇이 바뀌었는지 · 어떻게 적용하는지 · 남은 질문 하나.

## 3. 보안 원칙 (절대)
- 혜성물류 · 화주사 자료는 **외부 반출 금지**. 공유는 행님이 직접 승인한 사람만.
- 외부 전송 · 공유가 들어가는 작업은 **반드시 먼저 확인**.
- **물동량의 단가 · 금액은 기밀**: 엑셀을 읽는 순간 버림. 화면 · DB · 엑셀 받기 어디에도 남기지 않음 (권한으로 숨기는 게 아니라 아예 안 읽음). 회의 자료 근거 시트의 '단가' 칸도 버림.
- 프런트엔드에 service_role 키 · 비밀 키 절대 금지. `site/js/config.js` 는 비워 두고 업데이트 zip 에도 넣지 않음.
- 토큰(열쇠)은 **설치 · 업데이트 검은 창에만** 입력. 대화창 · 카톡 · 메일 · 코드 · 메모리에 쓰지 않음.
- 사방넷 · 버킷 개인정보(이름 · 전화 · 주소)는 계산에만 쓰고 저장하지 않음.
- 회사 실제 파일은 저장소 밖(예: `real/` — .gitignore)에만. `test/fx` 시험 파일 · `test/shots` 화면 사진에도 실제 숫자가 있을 수 있으니 **외부 저장소(GitHub 공개 등)에 올리지 말 것**.

## 4. 폴더
- `site/index.html` · `site/js/*.js` · `site/css/app.css` — 화면. 모듈은 `HS.view('이름', { render })` 로 등록, 메뉴는 `site/js/app.js` 의 NAV.
- `site/js/db.js` — Supabase 연결 + **로컬 모드(브라우저 저장 흉내)**: 테스트는 로컬 모드로 돌아감. 새 표를 만들면 여기 PK · 권한 규칙도 추가.
- `sql/01~22_*.sql` — DB. 새 SQL 은 번호를 이어서 만들고 `installer/install.ps1` 의 두 목록에 추가 (**파일 첫 바이트 BOM 유지** — 바이트 단위로 고칠 것). 업데이트하기.bat 이 새 SQL 을 자동 실행.
- `installer/install.ps1` · `설치하기.bat` · `업데이트하기.bat` — 설치 · 업데이트 (토큰은 사용자 PC 에 저장 선택 가능).
- `tools/mkzip.py` — 업데이트 zip 만들기: `python tools/mkzip.py <출력폴더> ERP_수정파일_MMDD_N.zip <안내문.txt>`
  - **출력폴더는 항상 상위 폴더 `클로드 코드\01. 혜성 회의`** (바탕화면 금지 · 2026-11-24 행님 지시). 지난 zip 들이 거기 모여 있다.
- `test/` — Playwright 화면 테스트 · `sqltest.mjs`(PGlite DB 테스트).

```
PORT=8766 node test/e2e_meetbook.js   # 화면 테스트 하나 (Windows PowerShell: $env:PORT=8766; node test\e2e_meetbook.js)

PORT=8766 node test/e2e_crawl.js     # 전체 화면 점검
```

- 폐기한 화면(`HS.RETIRED`: kpi · tasks · dashboard · supply · meetbook)과 폐기한 출고 지시 화면(`#/cs?k=order` · 배분LIST · 온라인 · 지시 조회 → WMS 재고로 되돌려짐)을 여는 옛 점검은 **2026-11-10 에 고쳐 둠**:
  - e2e_stock — `#/kpi` 팀 화면 재고 요약 부분을 뺌 (시즌 계획 · 월간 회의 월말 재고는 그대로 점검).
  - e2e_grid — 4번 "배분LIST 매장 칸 없이" 를 뺌 (표 기능 · 로케이션 없음 기준은 그대로).
  - e2e_query · e2e_cs — 폐기된 화면이 WMS 재고로 되돌려지는지 확인하도록 바꿈. e2e_cs 는 버킷 파일이 전산자료에서 안 쓰이는 것(종류 빈칸) · 대시보드에 배분지시 현황이 없는 것을 점검.
  - e2e_alloc — 전부 그 화면 점검이라 파일 맨 위 `console.log('SKIP …'); return;` 로 멈춰 둠. 화면을 되살리면 그 두 줄만 지우면 된다. DB 쪽 배분LIST 규칙(`erp_cs_alloc` · `erp_cs_alloc_merge`)은 `sqltest.mjs` 에서 그대로 점검.

## 6. 월간 회의 보고서 (2026-11-09 중심 기능)
- 매달 회의 자료 엑셀(약 25MB · 시트 22개)을 **[엑셀 올리기]** → `site/js/xlsxlite.js`(라이브러리 없이 필요한 시트만 압축 해제 · 서식 · 병합 · 숫자 서식 그대로) → `site/js/meetbook.js`(보라색 탭 = 대표님 보고서 → "1) 제목" 줄에서 장 나누기 · 다른 색 탭 = 근거 데이터 앞 300줄 · 숨긴 시트 제외 · 200MB 큰 시트는 "엑셀에서 보기") → DB `erp_meet_book` (sql/22).
- 화면 `site/js/views-meetbook.js`: 0장 핵심 요약 6칸 · 팀 탭 · ← → 넘기기 · [▶ 발표 모드] · [📎 엑셀 원본](대표님 모드 = 보라색만) · 장마다 [핵심 3줄] 메모.
- 읽기 좋은 표 `site/js/meetview.js`(제목줄 · TOTAL · 소계 · 비율 칸 계산식 a÷b 자동 인식) + `site/js/meetsmart.js`(접기형 소계 먼저 · 조건: 여러 개 고르기 · 찾기 쉼표 여러 개 · 비율 범위 · 0인 줄 숨김 · 주의만 · 선택 합계). [▦ 엑셀 모양] 버튼으로 원래 모양.
- 빨간색 기준: 입고률 30% 미만 · 출고률 50% 미만 (meetsmart.js `RULE`).
- 예전 ERP 자동 보고서는 메뉴 "자동 집계 보고서".
